STM32——串口DMA模式收发，与不定长数据接收

发表于 2026-07-30 分类于 嵌入式 阅读次数：
本文字数： 14k 阅读时长 ≈ 13 分钟
上一篇用中断模式解放了CPU——数据到了才处理，不用空等。但这还不够：每收发一个字节，CPU都要进一次中断去搬运数据，还是有点忙。这篇引入DMA（意为直接内存访问），给CPU找个"小助手"来专门搬数据。再结合串口空闲中断，实现不定长数据接收——发多少收多少，不用预先约定长度。

从中断到 DMA——CPU 还是太忙了

上篇博客，我们用串口中断模式解决了 CPU “傻等”的问题。回顾一下当时的代码结构：

CPU 确实不用空等了，但每次收发一个字节，CPU 都要进一次中断：

虽然每次中断处理时间很短，但数据量大的时候，CPU 频繁地在”正常任务”和”中断搬运”之间切换——时间都花在来回奔波上了。

这就好比：

DMA（Direct Memory Access，直接内存访问） 就是这个”助理”——它是一个独立于 CPU 的硬件模块，可以在不经过 CPU 的情况下，在外设寄存器和内存之间自动搬运数据。

DMA 原理

传统的数据搬运路径

先看看没有 DMA 时，串口接收的完整链路：

每收到一个字节，CPU 都要亲自从 USART2->DR 读到内存。发的时候反过来，也是要亲历亲为。

有了 DMA 之后

CPU 只需要做一件事：**告诉 DMA “把数据从 USART2->DR 搬到 receiveData，搬 N 次”**。DMA 就会在每次串口收到数据时自动搬走，全部搬完后再发一个中断通知 CPU。

DMA 的内部结构（简化版）

STM32F103 有 两个 DMA 控制器（DMA1 和 DMA2），每个控制器有 7 个通道。每个通道可以服务一个外设的请求：

DMA 通道需要的配置信息：

配置项 含义 类比
源地址 从哪里搬数据 仓库的位置
目标地址 搬到哪去 货架的位置
传输方向 外设→内存 / 内存→外设 / 内存→内存 从仓库到货架，还是从货架到仓库
传输数量 搬多少个数据 要搬多少箱货
地址自增 搬完一个后地址要不要+1 搬完一箱后，是在原地拿下一箱，还是往前走一步

在串口场景中

发送（内存 → 外设）：

  • 源地址：receiveData 数组（每次自增，因为要依次取数据）
  • 目标地址：USART2->DR 寄存器（不自增，因为每次都是写到同一个寄存器）
  • 方向：内存 → 外设

接收（外设 → 内存）：

  • 源地址：USART2->DR 寄存器（不自增，因为每次都是从这个寄存器读）
  • 目标地址：receiveData 数组（每次自增，因为要依次存到数组里）
  • 方向：外设 → 内存

关于 Mode：Normal vs Circular

这里 Mode 选了 Normal，意思是 DMA 搬运完指定字节数后就停止。

还有一种 Circular（循环模式），DMA 会在搬完后自动从头开始继续搬——适合连续、不间断的数据流场景（比如 ADC 连续采样）。这里我们只是收一条指令，Normal 就够了。

串口空闲中断的原理

串口有一个特殊的中断——空闲中断（IDLE Interrupt）。它的触发条件非常巧妙：

空闲中断不是在收到固定字节数时触发，而是在 RX 引脚从”忙碌”变为”空闲”时触发。 换句话说：

当串口收到一帧数据，然后对方停止发送了——RX 线变成空闲状态——硬件就触发空闲中断。

利用这个特性，我们可以实现：数据来了就收，对方停发了就知道收完了。

如果你只写上面这些代码，测试时可能会发现一个奇怪的现象——

发送短数据（比如 R1）：一切正常，完美回显。

发送长数据（比如超过 25 字节）：你会看到回显了两次！第一次回显了一半数据，第二次才回显完整数据。

这背后的”元凶”是 DMA 传输过半中断（Half-Transfer Interrupt，HT）。

为什么会触发两次？

回顾一下 HAL_UARTEx_ReceiveToIdle_DMA 的第二个参数：

DMA 的内部计数器设为 50（最大上限）。DMA 默认开启了一个叫传输过半中断的选项——当搬运的数量到达总数的一半（25 个） 时，也会触发一次中断。

所以如果你发送的数据超过了 25 字节：

RxEventCallback 被触发了两次：

  1. 第一次：DMA 收到 25 字节（过半中断触发）
  2. 第二次：RX 线空闲（真正的空闲中断触发）

这就导致了数据被重复处理。

行 代码 说明
(1) __HAL_RCC_DMA1_CLK_ENABLE() 开启 DMA1 外设时钟。和 GPIO 一样，DMA 也需要时钟才能工作
(2)(3) DMA1_Channel6_IRQn 通道6 的中断设置。前面 CubeMX 配置中，通道6分配给了 USART2_RX。所以这里使能的是接收完成后的 DMA 中断

这些中断在什么时候触发？当 DMA 完成了所有传输任务（搬运完指定数量的数据）后，会触发一个”传输完成中断”来通知 CPU。这个中断和我们之前学的串口中断不同：

USART2_IRQn 串口收到/发送了一个字节 串口外设
DMA1_Channel6/7_IRQn DMA 搬运完了所有数据 DMA 控制器

总结

到这里，串口通信这条学习路线就走完了三个台阶：

新知识点 说明
DMA（直接内存访问） 独立于 CPU 的硬件模块，自动在外设寄存器和内存之间搬运数据
DMA 通道 每个外设的 DMA 请求绑定到特定的 DMA 通道（USART2_TX → 通道7，USART2_RX → 通道6）
HAL_UART_Transmit_DMA / HAL_UART_Receive_DMA DMA 模式的串口收发函数，和 _IT 版本参数完全一致
空闲中断（Idle Interrupt） RX 线从忙碌变为空闲时触发，用于判断一帧数据接收完毕
HAL_UARTEx_ReceiveToIdle_DMA 基于 DMA + 空闲中断的接收函数，第三个参数是”最大接收长度”
HAL_UARTEx_RxEventCallback 不定长接收的回调函数，多了一个 Size 参数表示实际接收字节数
DMA 传输过半中断（HT） 默认开启的问题——搬运到一半也会触发回调，需要用 __HAL_DMA_DISABLE_IT 关闭
