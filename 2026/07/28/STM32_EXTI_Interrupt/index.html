STM32——红灯持续闪烁，绿灯用外部中断翻转状态

发表于 2026-07-28 分类于 嵌入式 阅读次数：
本文字数： 6.6k 阅读时长 ≈ 6 分钟
前面几篇博客都用的轮询方式处理按键，这次学习一个新的机制——外部中断（EXTI）。当按键按下时，CPU 停下当前工作，先去处理按键事件，处理完再回来继续原来的工作。作为入门 demo，实现一个经典功能：红灯持续闪烁时，按下 KEY1 按键触发外部中断，翻转绿灯的状态。

背景：为什么需要中断？

在前一篇按键输入博客中，KEY2 的”按一下翻转”功能用了轮询方式：

轮询的缺点很明显——如果 CPU 正在执行某个耗时操作，按键按下后要等到下一个循环才能被检测到，响应不及时。

中断的思路完全不同：

打个比方：

  • 轮询 = 你在写作业，每 5 秒抬头看一眼有没有人敲门
  • 中断 = 你在写作业，门铃响了（中断信号），你去开门，回来继续写

硬件原理

硬件与之前博客完全一样——KEY1（PB12，外部上拉）控制中断触发，红灯（PB0） 和 绿灯（PA7） 作为输出，高电平点亮。

逐行解释：

行号 代码 作用
① HAL_Delay(10) 机械按键按下瞬间会有抖动，电平在几毫秒内反复跳变。等 10ms 让电平稳定下来再读
② HAL_GPIO_ReadPin(...) 再次读取 KEY1 的电平，确认是真的按下了（低电平）。如果只是噪声干扰，不会误触发

④ HAL_GPIO_EXTI_IRQHandler(KEY1_Pin) 非常重要 清除 EXTI 的中断挂起标志位。如果不清除，中断会反复触发，程序卡死。函数里本身自带，不能删除。

关于中断优先级

CubeMX 中配置的优先级和实际生效的值之间有一个”编码”过程，理解了这个才能搞清中断嵌套行为。

优先级分组

STM32 的 NVIC 支持优先级分组，决定了抢占优先级和子优先级各占几位：

分组宏 抢占优先级 子优先级 适用场景
NVIC_PRIORITYGROUP_0 0 bit 4 bits 所有中断同级，不能嵌套
NVIC_PRIORITYGROUP_1 1 bit 3 bits 最多 2 级嵌套
NVIC_PRIORITYGROUP_2 2 bits 2 bits 最多 4 级嵌套
NVIC_PRIORITYGROUP_3 3 bits 1 bit 最多 8 级嵌套
NVIC_PRIORITYGROUP_4 4 bits 0 bits 最多 16 级嵌套（最常用）

CubeMX 默认使用 NVIC_PRIORITYGROUP_4——4 位全是抢占优先级，没有子优先级。

本次配置的优先级

中断 PreemptPriority 编码值 实际优先级
SysTick 14 0x00 0（最高）
EXTI15_10 15 0x80 8

数值越小优先级越高。SysTick 的优先级高于 EXTI，所以在 EXTI 中断服务函数中调用 HAL_Delay() 是安全的——SysTick 可以抢占 EXTI 来更新 uwTick 变量，不会死锁。

中断 vs 轮询的对比

这个 demo 正好可以和上一篇按键博客做一个对比：

对比项 轮询（上一篇 KEY2） 中断（本篇）
CPU 占用 高（一直在检测） 低（平时干正事，有事件才处理）
响应速度 取决于循环周期 立即响应
代码位置 main 循环里 中断服务函数中
主循环复杂度 按键逻辑和主逻辑混在一起 主循环只关心本职工作
适用场景 低频检测、简单系统 实时性要求高的场景

当然，中断也有代价——每次进入和退出中断都有上下文切换开销（保存现场、恢复现场），并且中断函数要尽量简短，否则会影响其他实时任务的响应。

进阶思路

1. 用回调函数分离逻辑

前面提到过，可以把中断处理逻辑写到 HAL_GPIO_EXTI_Callback 里，中断服务函数保持整洁。当项目中多个引脚共用一个 EXTI 中断线时（比如 EXTI15_10 同时服务 PB12 和 PB13），回调函数里用 GPIO_Pin 区分来源，代码结构更清晰。

2. 中断中只设标志位，主循环处理

标准的嵌入式写法——中断里只设一个 volatile 标志位：

主循环检测到标志位置位后，再执行消抖、翻转等操作。这样 ISR 的执行时间最短，对系统实时性的影响最小。

3. 上升沿 + 下降沿双触发

按键按下和松开都产生中断，可以用来检测”长按”和”短按”，或者做更精细的状态控制。

4. 优先级嵌套测试

可以给不同的外设中断配置不同的抢占优先级，观察高优先级中断打断低优先级中断的行为，加深对中断嵌套的理解。

总结

这次的收获：

  1. 外部中断（EXTI）的基本配置方法——CubeMX 里配引脚模式 + NVIC 设置
  2. 中断服务函数的写法——消抖 → 读引脚确认 → 执行逻辑 → 清标志位
  3. 中断优先级——优先级分组、优先级编码、抢占与嵌套的基本概念
  4. CMake 生成器的注意事项——NVIC 配置可能不会自动生成，需要手动检查

中断是嵌入式开发中非常重要的概念，后面学定时器、UART、I2C、SPI 等外设时都会用到中断机制。理解了这个 demo，后面的路会顺畅很多。
