数据结构 —— 链表

什么是链表

链表是线性表的另一种存储方式。与顺序表（数组）不同，链表的每个元素都是独立申请的一块内存（称为节点），通过指针把它们”串”起来。

两者核心区别：

顺序表 链表
内存 连续 离散（靠指针相连）
访问 随机访问 O(1)，按下标直接取 只能从头顺序访问 O(n)
插入/删除 O(n)，要移动大量元素 **O(1)**（改指针即可，前提是已找到位置）
扩容 需要拷贝整个数据区 天然”扩容”，随时 new 一个节点

一句话总结：**顺序表适合”查多改少”，链表适合”改多查少”**。

一、单向链表的结构定义

链式结构的代码套路是固定的：先定义节点结构，再定义表头结构，最后定义操作接口。

1.1 节点结构

节点 = 数据域 + 指针域。指针域存的是下一个节点的地址，这就是”链”的由来。

注意结构体里的写法是 struct LinkListNode* next 而不是 LinkListNode* next——因为此时 typedef 的名字 LinkListNode 还没有生效，必须用完整的 struct LinkListNode。

1.2 表头结构（含哨兵头节点）

注意：这里的 header 是一个节点结构体的”实体”（不是指针），它作为哨兵头节点存在。

为什么需要这个哨兵头节点？

因为有了它，所有插入删除的代码逻辑完全统一：

  • 没有哨兵时：插入到头部要改”头指针本身”，插入到中间要改”某个节点的 next”，两种情况的代码不一样，需要特判
  • 有哨兵时：插入位置的前置节点永远是某个节点的 next 字段（头插时前置节点就是哨兵 header），一套代码通吃

这就是”用空间换逻辑统一“的思想，也是 STL 里 list 等容器的常见做法。

二、创建与释放

2.1 创建表头

和顺序表一样，表头在堆区申请，返回指针。空链表的状态就是 header.next = NULL。

2.2 释放链表

释放的三大要点：

  1. 先备份再释放：temp = p; p = p->next; free(temp);——释放 p 之前必须先拿到下一个节点的地址，否则就”断链找不到了”
  2. 哨兵节点先不释放：遍历从 header.next 开始，哨兵 header 本身随表头一起释放
  3. 释放顺序与创建相反：先释放所有节点，再释放表头

三、插入操作

3.1 头插法（insertLinkListHeader）

核心两行，顺序不能反：

为什么先①后②？ 如果先写 p->next = new_node，原链就断了——new_node->next = p->next 拿到的将是新节点自己（自环），原节点全部丢失。**”先接新，再改旧”是链表插入的铁律。**

头插法的特点：插入顺序和最终顺序相反。循环头插 1~10，链里是 10 9 8 … 1。

3.2 任意位置插入（insertLinkListPos）

找前置节点的核心逻辑：单链表没有”回头路”，要插入到 pos 位置，必须先走到 pos-1 位置（前置节点），再改它的 next。

  • 哨兵下标约定为 -1，第一个真实节点下标为 0，所以前置节点的 index 是 pos-1
  • **pos 可以等于 num**：此时 p 会走到最后一个节点后面（next 为 NULL），插入后即为尾插——这就是 pos 范围写成 0~num 的原因

四、删除操作

三个关键点：

  1. 单链表删除为什么必须找”前置节点”？ 因为删除 = 让前一个节点的 next 跳过自己。而单链表只能顺着 next 往后走，无法回头，所以必须停在被删节点的前一个位置。代码里判断的是 p->next->val == val，p 始终站在前置位。
  2. 短路写法：while (p->next && p->next->val != val)——p->next 为 NULL（走到尾）时直接短路退出，不会去解引用 NULL。**”先判空、再取值”是遍历链表的铁律**。
  3. 备份思想：temp = p->next 把要删的节点备份下来，改链之后再 free(temp)。释放前必须先摘链，防止悬空。

五、没有头节点怎么办：dummy 虚拟头节点

上面所有操作之所以统一，全靠哨兵头节点。但如果链表只有头指针、没有哨兵呢？

没有哨兵时，头插的代码会很别扭——插入位置的前置节点不存在，必须特判”是不是插入到头部”。解决办法：在函数内部创建一个栈上的 dummy 虚拟头节点：

dummy 技巧的本质：在一个局部栈变量上”伪造”一个临时头节点，让头插、中间插、尾插共用同一套前置节点逻辑。函数结束后 dummy 自动销毁，但插入已经完成，header->next 同步为 dummy 的下一个——即最新的链头。

两种方案的取舍：

方案 优点 缺点
哨兵头节点（常驻） 逻辑统一、结构清晰 多一个节点开销
dummy 虚拟头节点（临时） 不占常驻内存 每次插入都要同步头指针

刷题时（LeetCode 等）没有哨兵头节点，dummy 技巧是最常用的解题手段，务必掌握。

六、单向循环链表：尾指针的妙用

循环链表 = 把最后一个节点的 next 指回开头，形成闭环。**配合尾指针 rear，尾插可以做到 O(1)**——这是它比普通链表强的地方。（对应代码：03_LinkLoop）

6.1 初始化

空循环链表的标志：header.next == &header（自己指向自己），这是循环链表”空表”和”遍历结束”的统一判断条件。初始化时 rear 也指向自身——因为空表只有一个节点（哨兵），它既是头又是尾。

6.2 尾插法（O(1) 的关键）

记住：循环链表尾插永远三步——接环、接入、更新 rear，和元素个数无关。

6.3 头插法的特殊处理

头插通常只动哨兵后面，rear 不变。唯一例外：空链表头插第一个节点——此时这个节点既是头也是尾，必须顺手更新 rear。这就是”创建第一个节点时，头尾指针一起指它“的经典处理。

6.4 遍历与释放

循环链表的遍历/释放终止条件从”p != NULL“变成了”p != &header“——因为最后一个节点的 next 指向的是哨兵头而不是 NULL。不能再用 NULL 判断，否则死循环。

七、双向循环链表：addNode / delNode 四指针

双向 = 每个节点多一个 prev 指针，可以往前走了。代码上最大的进步是：把”接缝”和”拆缝”封装成两个通用函数，头插尾插删除全部复用。（对应代码：04_DoubleLinkLoop）

注意这里的精巧设计：DoubleHeader 和 DoubleNode 是同一个结构体——表头本身就是一个哨兵节点实体。这是双向循环链表最常见的实现（STL 的 list 就是这个结构）。

空双向循环表：next == prev == 自身——整个表就一个哨兵节点。

四步的顺序其实没有严格要求（互不覆盖），但保持”先接新节点，再改老节点”的习惯最不容易出错。static 修饰表示它是文件内部工具函数，不对外暴露。

7.3 头插 / 尾插 / 删除，全是 addNode / delNode 的调用

双向链表的三大优势：

  1. 删除 O(1)：单链表删除必须找前置节点，双向链表 p->prev 直接就是前置，摘链只要两行（prev->next = next; next->prev = prev）
  2. 头插尾插完全对称：头插是 (header, header->next)，尾插是 (header->prev, header)，一套 addNode 通吃，没有任何特判
  3. 哨兵模式天然闭环：不需要维护 head/tail 两个指针，头尾操作都退化成”在哨兵身边插/删”

八、实战应用：约瑟夫环问题

约瑟夫问题（约瑟夫环）：n 个人围成一圈，从第 1 个人开始报数，报到 m 的人出列，下一个人重新从 1 报数，直到剩最后一个人。经典应用，天然适合用循环链表模拟。（对应代码：03_LinkLoop/Joseph.c）

8.1 问题建模

注意这里没有哨兵节点，只有头尾两个指针——因为约瑟夫环要频繁”转圈报数”，头尾指针直接定位最方便。它依然是循环链表（tail->next == head）。

8.2 初始化：尾插建环 + 首尾相接

**”空表首节点头尾同指，后续节点只动尾指针，最后一句闭环”**——没有哨兵时建循环链表的固定套路。每次插入末尾都执行 tail->next = head，保证环永远闭合。

8.3 遍历：do-while 的用武之地

普通循环链表有哨兵，用 while (p != &header)；**无哨兵的循环链表必须用 do-while**——因为第一次进来 p 就是合法节点，判断放在后面才能完整走完一圈再停。

8.4 核心：淘汰逻辑（pre / cur 双指针）

逐行拆解：

  1. 为什么报 m 次只走 m-1 步？ 因为 cur 初始已经站在第 1 个人上，for (i=1; i<m; i++) 再走 m-1 步正好停在报到 m 的人身上
  2. 为什么需要 pre？ 这是无哨兵的单向链表，删除仍然要找前置节点——pre 就是干这个的
  3. 淘汰三步：pre->next = cur->next（摘链）→ free(cur)（释放）→ cur = pre->next（从下一个人重新开始报数）
  4. **终止条件 cur->next != cur**：环上只剩一个节点时，它自己指向自己——这是”单节点环”的标志，跳出后它即幸存者

九、复习要点总结

9.1 四版链表代码对照

版本 表头结构 空表标志 遍历终止 亮点
单向链表（带头节点） 哨兵 header + num header.next == NULL p != NULL 插入删除逻辑统一
单向链表（无头节点） 头指针 next next == NULL p != NULL dummy 虚拟头节点技巧
单向循环链表 哨兵 + 尾指针 rear next == &header p != &header 尾插 O(1)
双向循环链表 哨兵即表头 next == prev == &header p != &header addNode/delNode 通用

9.2 操作复杂度

操作 单链表（带头） 循环链表（带 rear） 双向循环链表
头插 O(1) O(1) O(1)
尾插 O(n)（要遍历） O(1) O(1)
任意位置插入 O(n) O(n) O(n)
按值删除 O(n)（找前置） O(n) O(n)，但找到后摘链 O(1)
查找 O(n) O(n) O(n)

9.3 面试常问细节

  1. 为什么要哨兵头节点？ — 让头插和中间插共用”前置节点”逻辑，删除也无需特判”删的是不是第一个”，代码统一、不易出错
  2. 单链表删除为什么必须找前置节点？ — 单向链表只能顺着 next 走，删除的本质是”前一个节点跳过自己”，而前一个节点无法回头访问，只能先走到它
  3. 插入时”先接新、再改旧”为什么不能反？ — 先改旧会让原链断开，新节点无法挂接，后续节点全部丢失
  4. 循环链表如何判断空表和遍历结束？ — 统一用 p == &header（有哨兵）或 p == head（无哨兵），永远不能用 NULL
  5. 为什么循环链表尾插能 O(1)？ — 尾指针 rear 直接定位尾节点，免去 O(n) 的找尾遍历
  6. 双向循环链表删除为什么更优？ — 节点自带 prev，前置节点 O(1) 可得，摘链只需 delNode(p->prev, p->next) 两行
  7. dummy 虚拟头节点什么时候用？ — 刷题时链表常常只有头指针，局部创建 dummy 即可复用统一的插入逻辑，无需修改调用方的头指针（注意同步 header->next = dummy.next）
  8. 为什么要有 ElemType？ — 数据结构只关心”组织方式”不关心”元素类型”，typedef 一次，换类型只改一行
